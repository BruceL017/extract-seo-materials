# Extract SEO Materials

Turn product-development conversations into traceable SEO source material for OpenAI Codex.

[中文](README.md) | [Installation](#installation) | [Usage](#usage) | [Workflow](#workflow) | [Output structure](#output-structure) | [Safety boundaries](#safety-boundaries)

Extract SEO Materials is a Codex Skill that extracts reusable, traceable SEO source material from a developer's current product-development conversation and preserves it for ongoing accumulation.

If the current conversation contains qualifying material, one run first creates a timestamped session document. It then reads existing session material in the same project and completely rebuilds the single project summary. Separate conversations do not need direct access to one another; they contribute to shared topics through Markdown files in the project directory.

The Skill focuses on the information most likely to be lost during development: user problems, concrete scenarios, explanations, engineering conclusions, verification evidence, failed approaches, risks, limitations, and the questions users may search for.

It does not write finished SEO articles or generate search volume, keyword difficulty, or SERP conclusions.

## Installation

Use the built-in `$skill-installer` in Codex:

```text
Use $skill-installer to install https://github.com/BruceL017/extract-seo-materials. The Skill is located at the repository root.
```

Alternatively, run the installer script:

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo BruceL017/extract-seo-materials \
  --path . \
  --name extract-seo-materials
```

The default installation path is:

```text
~/.codex/skills/extract-seo-materials
```

After installation, use the Skill in a new Codex task.

## Usage

Explicit invocation:

```text
Use $extract-seo-materials to summarize SEO source material from the current conversation and rebuild the project summary.
```

You can also use natural-language requests such as:

- Summarize SEO material from the current conversation
- Extract SEO source material from the current conversation
- Update the project SEO material summary
- SEO source material
- SEO material
- Save the useful content from this development session

For best results, run the Skill after a development task is complete and its key conclusions are clear.

## Workflow

Each invocation runs two stages in order.

### Stage 1: Extract the current conversation

- Use only the currently visible developer-Agent conversation.
- Organize material around user-visible problems instead of listing code changes or development logs.
- Create at most one new session document per run; one document may contain multiple user-problem material packages.
- If no material qualifies, do not create a session document, but continue to rebuild the project summary.
- Do not read other Codex conversations or scan the source repository to enrich the material.

### Stage 2: Rebuild the project summary

- Read only session documents recognized by this Skill from `_content_materials/sessions/` in the current project.
- Group topics by the underlying user problem and search intent.
- Merge duplicate conclusions while retaining every source label.
- Record revisions or conflicts across conversations instead of silently replacing earlier conclusions.
- On every successful rebuild, regenerate the single summary from all session sources; never use the previous summary as an input.

This file-based workflow allows multiple independent development conversations in the same project to gradually build up the source material needed for one SEO article.

## Output structure

All generated files remain inside the current project:

```text
_content_materials/
├── sessions/
│   ├── 20260817-153045-login-timeout.md
│   ├── 20260818-101230-session-recovery.md
│   └── ...
└── summary/
    └── project-seo-materials.md
```

- Documents in `sessions/` are timestamped historical sources. They are append-only and are not automatically overwritten or deleted.
- `project-seo-materials.md` is the single derived summary and is replaced only after a successful full rebuild.
- Important facts, conclusions, failed approaches, and limitations in the summary use source labels such as `[S001]` and `[S002]` for traceability.
- The summary is generated by the Skill. Manual edits are overwritten by the next successful rebuild.

Each material package can record:

- The user problem and concrete scenario
- Related products, modules, and domain entities
- The relevant discussion and explicit conclusions
- Contribution types and fact states
- Why the topic matters to ordinary users
- Search intent and natural-language queries
- Key points reusable in later content production
- Missing evidence or details that another conversation should supply

Generated documents retain the exact controlled fact states `已验证事实` (verified fact), `工程结论` (engineering conclusion), `待验证假设` (hypothesis to verify), and `失败方案` (failed approach). The project summary assigns one of three maturity levels: `素材不足` (insufficient material), `可形成内容简报` (ready for a content brief), or `可进入文章写作` (ready for article drafting).

See the [output contract](references/output-contract.md) for the complete schema and merge rules.

## Safety boundaries

The Skill does not write the following into material documents:

- API keys, tokens, credentials, or private endpoints
- Personal data or identity-linked accounts and addresses
- Exploitable vulnerability details
- Implementation facts not explicitly discussed in the current conversation
- Search volume, keyword difficulty, or SERP conclusions inferred from external SEO services

Unreleased features and commercially sensitive decisions are included only when essential, reduced to the minimum necessary summary, and marked `发布前确认` (confirm before publication).

## Scope

The Skill works across Web3, SaaS, developer tools, ecommerce, and other product domains. It is not limited to a specific industry.

It collects SEO source material; it does not handle article drafting, editorial review, publishing, or performance monitoring. The current working directory is the project boundary, and the Skill does not aggregate across repositories.
